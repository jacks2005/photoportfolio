# Jack Simpson — photographic archive

Static HTML generated with Python and Pillow. GitHub Pages continues to build and deploy on pushes to `main`.

## Build and preview

```sh
pip install -r requirements.txt
python build.py
python -m http.server 8000 --bind 127.0.0.1
```

Open http://127.0.0.1:8000/.

`python build.py` retains the existing photo import workflow: JPEG/TIFF files placed directly in a collection folder are sorted by EXIF `DateTimeOriginal`, converted into numbered full and thumbnail WebPs, then the imported JPEG/TIFF files are deleted. Undated imports sort by filename and appear after dated photographs in the generated newest-first gallery. To regenerate only the pages without importing photographs:

```sh
python -c 'import build; build.build_site()'
```

To renumber existing full/thumbnail WebP pairs into the same capture-date order, preview the changes first and then run the sorter:

```sh
python sort_existing_photos.py --dry-run
python sort_existing_photos.py
```

The sorter validates that every full image has a matching thumbnail, preserves filename-based `cover` and `photo_layouts` settings in `collections.json`, and is safe to run repeatedly. It renames files only; regenerate the pages afterward with the command above.

Edit the templates, stylesheet, script, or generator, then regenerate the checked-in HTML pages. `base_template.html` holds the shared navigation and page shell. Home and gallery content use their respective templates; Archive is generated by `build.py`.

## Collections and metadata

Every non-empty folder under `photos/` with matching `thumbs/` and `full/` WebPs becomes a gallery. Folders starting with `_` are site assets. `photos/all/` remains an independent All Photos inventory and is excluded from the project count.

Projects sort alphabetically. Numbered images sort descending, preserving the original site order; each project's first image is its default index cover. Photographs retain their existing files and color profiles.

Capture dates come only from EXIF `DateTimeOriginal`, without timezone conversion or clock correction. Missing/invalid capture dates are omitted; projects without any dates appear under “Undated.” Collection ranges use the minimum and maximum available capture dates. Archive groups use the latest capture year. Export timestamps are not used. Camera, lens, and exposure details are included only when present.

Optional overrides go in `collections.json`, keyed by the folder name. Omitted fields keep generated defaults. Example:

```json
{
  "berlin": {
    "title": "Berlin",
    "location": "Berlin, Germany",
    "dates": ["2024-04-29", "2024-04-30"],
    "cover": "image-4.webp"
  }
}
```

`dates` is an inclusive pair of ISO dates; use the same date twice for a single day. It changes the collection heading and archive grouping, leaving individual EXIF captions unchanged. `cover` must name an existing image in that collection and changes only the index preview, preserving gallery order. Invalid covers and reversed date ranges fail the build with an explanatory error.

Fonts use the existing Google Fonts loading approach, with local serif, sans, and monospace fallbacks. JavaScript enhances previews and the native dialog viewer. Collection links, archive disclosures, and links to full images also work without JavaScript.

## Art direction for individual photographs

Set layouts by filename in `collections.json`. The following example puts Berlin's photos on separate rows except for a deliberate pair:

```json
{
  "berlin": {
    "default_layout": "solo",
    "photo_layouts": {
      "image-6.webp": "solo",
      "image-5.webp": "pair-next",
      "image-3.webp": "left",
      "image-2.webp": "right",
      "image-1.webp": "wide"
    }
  }
}
```

Merge these fields into any existing collection settings rather than replacing its title, cover, or dates.

| Layout | Presentation |
| --- | --- |
| `solo` | One centered photo on its own row. |
| `wide` | One photo using the full grid width. |
| `centered` | One photo using the central eight columns. |
| `left` | One photo in the left five columns, on its own row. |
| `right` | One photo in the right six columns, on its own row. |
| `pair-next` | This photo and the next photo share a row, aligned at the top. Works with any orientation. |
| `auto` | Use a consistent, centered image size on its own row. Pairing and left/right alignment are only used when explicitly selected. |

`default_layout` accepts `auto` (the existing default) or `solo`. Individual entries override it. Unlisted photographs use the collection default. Remove an entry to return it to the default. An empty `collections.json` displays every project photo on its own row, regardless of orientation. Only `pair-next` creates a pair.

“Next” means the next image in the existing descending gallery order: in the example, `image-5.webp` pairs with `image-4.webp`. Leave the second image's layout unset (or `auto`). A pair cannot consume an image with another explicit layout or overlap another pair. Unknown filenames, unknown layouts, and pairing the last image fail the build before pages are written.

Single-photo rows never accidentally share space with another row. All orientations share a target height capped at 560px, 65% of the viewport height, and the viewport height minus 220px for navigation and captions. Images are also limited to 900px wide and their available column width, without cropping or distortion. These limits apply to every layout, including `wide`. On mobile, pairs stack in the original order. These settings affect project pages only; Archive and All Photos retain their contact sheets.

After editing, regenerate the pages and refresh your local preview:

```sh
python -c 'import build; build.build_site()'
```

## Validation

```sh
python -m unittest -v test_build
node --test test_script.cjs
```

Generator tests use temporary fixtures and do not import or change portfolio photographs. Browser acceptance covers the desktop index, keyboard previews, mobile stacking, native archive disclosures, and lightbox focus restoration, wraparound, loading, and errors.
